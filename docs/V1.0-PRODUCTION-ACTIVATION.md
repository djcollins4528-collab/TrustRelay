# TrustRelay v1.0 Commercial Production Activation Runbook

TrustRelay is designed to fail closed until every required platform and organization gate is satisfied.

## Platform gates

Required controls currently tracked in `production_readiness_controls` include:

- separate production backend/environment;
- production billing provider;
- contracting legal entity;
- counsel review and effective binding legal package;
- custom domain;
- custom SMTP;
- database SSL and network restrictions;
- backup/PITR and tested recovery;
- monitored security contact;
- retention automation;
- malware scanning for uploaded evidence;
- incident-response procedure/ownership;
- privacy-request process;
- reviewer governance;
- Auth abuse/rate-limit/CAPTCHA controls;
- clean TrustRelay-specific security advisor state.

A service-role operator must attach evidence and mark controls pass only after verification.

## Organization gates

Before an organization may request activation:
- HTTPS website;
- primary, security and billing contacts;
- legal entity name;
- current binding Business Terms/DPA/AUP accepted;
- active/trial/manual-contract billing;
- at least one active owner.

## Activation

1. Organization submits production activation request.
2. TrustRelay reviews platform and organization controls.
3. Service-role production approval changes organization mode to `live`.
4. Partner API continues checking production approval and billable status on every new live decision.
5. If billing later becomes invalid, new live decisions fail closed.

## Search indexing

The current v1.0 candidate pages use `noindex`. Remove this only after the custom domain, effective legal package and commercial launch approval are complete.
