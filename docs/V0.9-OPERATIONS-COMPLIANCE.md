# TrustRelay v0.9 — Webhooks, Notifications, RBAC, and Compliance/Audit Exports

Date: 2026-10-01

## Scope

v0.9 adds four operational layers to TrustRelay:

1. durable signed webhooks
2. account notifications and preferences
3. permission-based organization roles
4. private compliance/audit exports

The v0.8 identity-proofing, private evidence, signed-credential and live-assurance boundaries remain intact.

### Member lifecycle

Supported membership states:

- active
- disabled
- removed

Supported management operations:

- change role
- disable
- restore
- remove
- transfer ownership

Ownership is not an ordinary selectable role change. Ownership transfer is explicit and atomic: the old owner becomes admin and the new owner becomes owner.

Every membership mutation records:

- actor
- old/new role where applicable
- resulting member state
- timestamp
- organization audit event
- account notification
- organization webhook event

## 2. Organization audit ledger

Table:

`organization_audit_events`

Each organization has an independent SHA-256 hash chain.

The append path uses a per-organization advisory lock so concurrent mutations cannot fork the chain.

The Verifier Portal can verify the organization chain with:

`trustrelay_verify_org_audit_chain_v09`

Compliance exports also snapshot the chain's validity/head state at generation time.

The older global authorization audit chain remains in place for decision evidence.

Secrets:

- generated randomly
- stored encrypted in Supabase Vault

### Signing

Headers:

- `X-TrustRelay-Event`
- `X-TrustRelay-Delivery`
- `X-TrustRelay-Timestamp`
- `X-TrustRelay-Signature`

Signature:

HMAC-SHA256 over:

`<timestamp>.<payload>`

Header form:

`v1=<lowercase hex digest>`

### Delivery state

- pending
- dispatched
- retrying
- delivered
- dead_letter

Per-attempt records are stored in:

`webhook_delivery_attempts`

Delivery rows retain:

- payload SHA-256
- attempt count
- response status
- last error
- next retry timestamp
- delivered/dead-letter timestamps

### Maintenance scheduler

Exactly one active cron job remains canonical:

`trustrelay-webhook-maintenance-v09`

Schedule:

`* * * * *`

It reconciles completed deliveries, applies retry/dead-letter state, then dispatches due work. For v1.0, `pg_net` calls only the fixed internal `trustrelay-webhook-egress-v10` Edge Function. That egress function resolves A/AAAA records immediately before delivery, rejects private/reserved answers, pins the TCP socket to a validated public IP, upgrades that socket to TLS using the original hostname for certificate validation, and never follows redirects.

### Endpoint controls

Webhook endpoints require HTTPS. Creation-time validation still rejects obvious local/private targets and URL user-info. Delivery-time validation is authoritative: DNS is re-resolved on each attempt, every returned address must be public, the outbound socket is pinned to the selected validated address, and redirects are blocked.

## 5. Compliance and audit exports

Edge Function:

`trustrelay-compliance-export-v09`

Private bucket:

`trustrelay-compliance-exports`

Bucket policy:

- private
- 25 MiB limit
- application/json and text/csv only

Access roles:

- owner
- admin
- compliance
- auditor

Verifier is intentionally denied `audit.export`.

### Time bounds

Default:

30 days ending at generation time

Maximum:

366 days

### Selectable data

- authorization decisions
- organization audit events
- authorization audit evidence
- webhook subscriptions/deliveries/attempts
- organization members/invitations
- evidence-request workflow metadata
- partner API-key metadata
- organization notifications

API-key metadata excludes hashes and raw key values.

Evidence data excludes private document bodies.

### Artifact integrity

The export service:

1. creates an authorized export request
2. assembles organization-scoped server-side data
3. creates JSON or CSV bytes
4. hashes the exact bytes with SHA-256
5. uploads them to private Storage
6. records row count and byte size
7. records organization audit-chain status
8. links the export into a per-organization export hash chain
9. emits an export-ready notification/webhook

The export record includes:

- content SHA-256
- previous export hash
- current export hash
- generated/completed time
- expiry
- selected scopes

Signed download URL lifetime:

300 seconds

Export metadata/object access window:

24 hours

## 7. Security checkpoint

Supabase Security Advisor after v0.9 reports only:

`Leaked Password Protection Disabled`

This is the known Supabase Free-plan warning. TrustRelay uses passwordless email magic-link/OTP and does not ask application users to create TrustRelay passwords.

There are no current v0.9 RLS or exposed SECURITY DEFINER findings.

Performance Advisor has no unindexed foreign-key warnings. INFO-level unused-index notices are expected on the low-traffic staging database.
