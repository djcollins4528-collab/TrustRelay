## Release-gate corrections completed

The final v0.9/v1.0 gate uncovered and corrected two production-candidate issues:

1. **Database/repository drift** — four live v1.0 operational-hardening migrations were missing from the canonical repository. Their exact applied statement order is now recorded in `supabase/migrations/0005_recorded_v10_operational_hardening.sql`.
2. **Privacy readiness status bug** — the readiness function treated `withdrawn` as closed even though the actual privacy workflow uses `cancelled`. The function now correctly treats `completed`, `denied`, and `cancelled` as terminal for deadline readiness.

The interrupted Render-relay migration remains recorded as historical migration `0006`; the final Edge egress foundation and pinned-TLS override are recorded in `0007` and `0008`.

## Explicit blockers to commercial production

TrustRelay v1.0 will not call itself commercially live until:

- separate production Supabase environment is approved/provisioned
- Stripe live provider/secrets/price IDs are configured
- legal entity is confirmed
- counsel approves and effective binding legal package is published
- custom domain is attached
- custom SMTP is configured
- database SSL/network controls are confirmed
- production backup configuration and restore exercise are confirmed (current Supabase organization is Free, so this is presently a hard blocker)
- monitored security contact exists
- evidence malware scanning is integrated
- production reviewer governance is approved
- counsel-approved retention periods/actions are configured and the existing dry-run automation is promoted through an approved destructive-retention process when appropriate
- privacy-request operations are staffed
- Auth abuse/CAPTCHA controls are confirmed
- incident response ownership is assigned

The production activation engine enforces these controls rather than relying on a checklist alone.
