# TrustRelay v0.6.1 — User Experience Layer

## Staging App

- Render static site: https://trustrelay-app-staging.onrender.com
- Application path: /web/
- Root launcher preserves query parameters and URL fragments and forwards into /web/.
- Source: `web/index.html`, `web/styles.css`, `web/app.js`

## Authentication

The browser uses the modern Supabase publishable key only. No Supabase secret/service-role key is shipped to the client.

Pinned browser SDK:

- `@supabase/supabase-js@2.117.2`

Supported flows:

- Passwordless email magic-link sign-in
- Passwordless first-use account creation
- Optional six-digit email OTP verification when the Auth email template uses `{{ .Token }}`
- Confirmed-email staging assurance
- Persistent authenticated session
- Sign-out

TrustRelay v0.6.1 no longer exposes password creation, password sign-in, or password-recovery UI. The browser calls Supabase `signInWithOtp`; by default Supabase sends a one-time Magic Link when the email template contains `{{ .ConfirmationURL }}`.

Confirmed email is treated as `email_verified` pilot assurance for staging. This is explicitly labeled in the UI as lower assurance than document/KYC/notary verification.

## Principal Experience

A principal can:

- View all authority relationships
- Filter principal vs representative relationships
- Create a new authority grant
- Select allowed actions
- Select resource scopes
- Add custom action/resource identifiers
- Set validity start and expiration
- Set maximum transaction amount
- Restrict allowed currency
- Require supporting evidence
- Configure escalation above amount limits
- Generate a one-time representative invitation
- Copy or email the invitation link
- Issue/rotate a signed credential after activation
- Revoke the grant

Revocation also revokes all active credentials for the grant.

## Representative Experience

A representative can:

- Sign in with the invited email address
- Open an invitation URL
- Preview the complete authority scope before acceptance
- See principal, validity window, actions, resources, amount limit and evidence requirements
- Explicitly accept scoped authority
- View active authority relationships
- Issue/rotate credentials when the grant is active

Invitation acceptance is email-bound. The representative cannot expand the grant scope.

## Credential Experience

Active grants can issue compact ES256 TrustRelay authority credentials.

The UI supports:

- Credential issue/rotation
- Copy credential
- Download as `.jwt`
- Credential JTI, key ID, algorithm and expiration display
- Public verification without a TrustRelay account

The public verifier checks the deployed `trustrelay-credential-verify-v06` function and displays the live verification reason plus authority scope for valid credentials.

## Required hosted Auth URL setting

Supabase hosted Auth must use the following Site URL for staging:

`https://trustrelay-app-staging.onrender.com`

Add the same domain to Redirect URLs. For staging, the recommended allow-list entry is:

`https://trustrelay-app-staging.onrender.com/**`

The client intentionally uses the root origin for passwordless Magic Link redirects and preserves a pending representative invitation across the authentication round-trip.

## Security checkpoint

At the v0.6.1 checkpoint:

- TrustRelay's application authentication flow is passwordless, eliminating application password creation and password reuse risk.
- Supabase may continue to report the plan-gated "Leaked Password Protection" Auth warning on Free because HaveIBeenPwned password screening is a Pro feature; the TrustRelay UI itself no longer accepts passwords.
- Public browser code contains only the publishable key.
- Service-role/secret keys remain server-side.
- Signing private JWKs remain encrypted in Supabase Vault.
- Invitation tokens are stored only as SHA-256 hashes.
- Participant data is protected by RLS.
- Privileged workflow bodies remain in the non-exposed private schema or JWT-protected Edge Functions.
