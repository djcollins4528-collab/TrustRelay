## Partner API

Endpoints:

- GET /healthz
- POST /v1/decisions/evaluate
- GET /v1/decisions/{requestId}

Authentication:

- X-TrustRelay-Key
- raw external keys are shown once
- only SHA-256 hashes are stored
- sandbox keys use tr_test_ prefix
- per-key scopes are enforced
- revoked and expired keys are rejected
- rate limiting is enforced

Supported scopes:

- decisions:read
- decisions:write

## Portal security boundary

The browser never receives an organization portal API key.

Each organization gets an internal portal key whose raw value is encrypted in Supabase Vault. The authenticated verifier bridge retrieves that key server-side and calls the same Partner API used by external integrations. Portal decisions are tagged source=portal.

## Decision engine

Outcomes:

- ALLOW
- DENY
- ESCALATE

Current rule support:

- allowed/prohibited actions
- exact and wildcard resources
- maximum amount
- allowed currencies
- required evidence
- above-limit escalation
- always-escalate
- unknown policy rules conservatively escalate

The Partner API verifies the signed TrustRelay credential before evaluating the requested operation.

## Webhooks

Supported events:

- decision.created
- grant.revoked
- credential.revoked

Delivery signing:

HMAC-SHA256 over:

<timestamp>.<raw_body>

Headers:

- X-TrustRelay-Event
- X-TrustRelay-Delivery
- X-TrustRelay-Timestamp
- X-TrustRelay-Signature

Webhook secrets are encrypted in Supabase Vault.

Webhook endpoint creation rejects obvious localhost, link-local, private IPv4, .local, URL-userinfo, and literal IPv6 targets to reduce SSRF exposure.

## Known test boundary

A single fully automated test that combined genuine Supabase user sessions, a raw partner API key, and a raw TrustRelay credential in one disposable harness was intentionally not completed because the execution environment blocked combining those live secrets.

TrustRelay therefore does not claim that specific all-in-one automated harness passed.

The underlying components, policy engine, key validation, persistence, RBAC, webhook queue/signing path, and live HTTP boundary were tested independently as described above.

## Security checkpoint

Supabase Security Advisor has no v0.7 database/RLS/security-definer findings.

The one remaining Auth advisory is:

- Leaked Password Protection Disabled

That feature is unavailable on the current Supabase Free plan. TrustRelay's user-facing authentication is passwordless magic-link/OTP, so the application itself does not accept user passwords.

## Cleanup

The legacy password-based v0.6.1 pilot endpoint was retired and now requires JWT verification while returning HTTP 410.

No raw partner keys, webhook signing secrets, private credential signing keys, Auth session tokens, or credential tokens are committed to the repository.
