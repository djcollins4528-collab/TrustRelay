## Backup and disaster recovery

Nightly off-project encrypted recovery is active.

- source: production Supabase project
- sink: separate TrustRelay staging Supabase project
- schedule: daily 04:17 UTC
- transport authentication: ES256-signed server-to-server requests
- payload encryption: fresh AES-256-GCM key per backup run
- key recovery: RSA-OAEP-256 public-key wrapping with the recovery private key held in staging Vault
- Storage objects are included automatically
- Auth sessions, refresh tokens, Vault plaintext and live runtime secrets are intentionally excluded and must be rotated/reprovisioned during disaster recovery

## Identity-review operating model

Manual identity proofing/review is disabled at the database boundary for the current solo-operator model. Proofing start/submission and reviewer context fail closed with `MANUAL_IDENTITY_REVIEW_DISABLED`.

If manual identity review is enabled later, production requires at least two independent approved, trained, unexpired reviewers.

## Billing and commercial activation

Dedicated TrustRelay live and sandbox Stripe infrastructure is active and isolated.

Production Checkout now performs a platform-readiness check before creating a Stripe Checkout Session. While any required control remains open it returns `COMMERCIAL_LAUNCH_NOT_READY`, preventing accidental production charges before launch approval.

Organization production activation independently checks platform and organization readiness before entering live mode.

## Final launch sequence

1. Acquire and attach the production custom domain.
2. Confirm the contracting entity/business address.
3. Obtain qualified legal review.
4. Publish the approved legal package with effective dates.
5. Approve retention periods/actions and enable the approved automation.
6. Re-run objective readiness.
7. Only then permit production Checkout and live organization activation.
