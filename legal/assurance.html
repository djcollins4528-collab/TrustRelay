ENTERPRISE DILIGENCE · CURRENT CONTROL SUMMARY

Security & Assurance Factsheet

A concise summary of controls implemented in the TrustRelay production-candidate platform. This factsheet distinguishes implemented engineering from external assurance, contractual commitments, and certifications that are still pending.

Scope. This page is an operational assurance summary, not a certification, audit opinion, legal representation, or substitute for a customer-specific security review.

Identity & access

Enterprise access is bounded and auditable.

Authentication and authorization controls are separated so possession of an identity is not equivalent to permission to perform sensitive institutional actions.

Passwordless user authentication

Email magic-link/OTP avoids reusable user passwords in the normal account flow.

AuthenticationImplemented

Enterprise SSO

Organization SSO supports Microsoft Entra ID and Okta with server-enforced organization policy and lockout protections.

SSOImplemented

SCIM lifecycle

SCIM 2.0 supports user lifecycle, Group Push, membership synchronization, and safe enterprise role mapping.

ProvisioningImplemented

Privilege boundary

SCIM cannot assign Owner or Admin and does not take over manually managed or privileged memberships.

Least privilegeEnforced

Application & data

Sensitive operations stay on trusted paths.

TrustRelay uses server-side authorization, private storage, explicit evidence-sharing workflows, and integrity records to reduce browser and client trust.

Server-enforced RBAC

Organization roles and privileged operations are enforced by trusted server functions rather than presentation-layer controls alone.

Private evidence storage

Identity and supporting evidence is kept private and exposed only through bounded workflow-controlled access paths.

Cryptographic integrity

Authority credentials use ES256 signing; evidence and export artifacts use SHA-256 integrity hashes; organization activity uses hash-linked audit evidence.

Scoped integrations

Partner API keys are scope-limited and stored as hashes. Webhooks use signed delivery with retry and delivery-history controls.

Secure delivery & operations

Changes are gated before production.

Production deploys use an approved-commit gate and separate production and staging environments. Security checks are integrated into the delivery workflow.
