Quick start

Your first authority decision.

Use a server-side sandbox API key and a signed TrustRelay authority credential.

1
Create a sandbox organization

Open the Verifier Portal, create your organization, and complete the sandbox onboarding flow.

2
Create an API key

Owners, admins, and developers can create keys. Give the integration only the scopes it needs: decisions:write and/or decisions:read.

3
Store the raw key once

The raw partner key is shown once. Keep it in a server-side secret store. TrustRelay stores only its SHA-256 hash.

4
Evaluate the action

POST a unique request ID, signed credential, action, and resource to the decision endpoint.

Authentication

Server-side keys only.

Send the partner key in the X-TrustRelay-Key header. Never expose a partner key to browser JavaScript, mobile applications, source repositories, URLs, query strings, analytics, or application logs.

Key scopes

decisions:write
Evaluate delegated authority.
decisions:read
Retrieve an existing decision by request ID.

Key lifecycle

Create and revoke partner keys from the Verifier Portal. The raw key is returned only at creation; TrustRelay persists its SHA-256 hash rather than the reusable secret.

Webhooks

Receive signed lifecycle events.

Webhook endpoints must use HTTPS. TrustRelay signs each delivery with a secret that is shown once at creation or rotation and protected server-side afterward.

X-TrustRelay-EventEvent type
X-TrustRelay-DeliveryUnique delivery identifier
X-TrustRelay-TimestampSignature timestamp
X-TrustRelay-Signaturev1=<lowercase hex digest>

Signature input

<timestamp>.<raw_request_body>HMAC-SHA256 with your webhook signing secret
Node.jsWebhook verification
import crypto from "node:crypto";

function verifyTrustRelayWebhook({ rawBody, timestamp, signature, secret }) {
  const expected =
    "v1=" +
    crypto.createHmac("sha256", secret)
      .update(`${timestamp}.${rawBody}`)
      .digest("hex");

  const a = Buffer.from(expected);
  const b = Buffer.from(signature);

  return a.length === b.length && crypto.timingSafeEqual(a, b);
}

Verify the signature against the exact raw request body before parsing JSON, use constant-time comparison, and reject timestamps outside your accepted replay window. Do not follow webhook redirects on your receiving-side assumptions.

Rate limits

Sandbox default: 120 requests per 60 seconds.

Partner API rate state is scoped to the organization key. The TrustRelay gateway also applies runtime abuse protections. Treat a returned 429 and any Retry-After value as authoritative.

Integration security

Production-minded defaults.

✓

Keep API keys server-side. Never embed a partner key in a browser or distributed client.

✓

Use least-privilege scopes. Separate read-only and write-capable integrations when practical.

✓

Make request IDs durable. Persist your idempotency key with the business operation it protects.

✓

Validate webhook signatures first. Authenticate the raw body before deserialization or business processing.

✓

Rotate secrets deliberately. Revoke unused API keys and rotate webhook signing secrets through the Verifier Portal.

✓

Log references, not secrets. Keep raw API keys, credentials, signing secrets, and sensitive evidence out of logs.
